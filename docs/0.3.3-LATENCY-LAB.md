# GreenVita 0.3.3 latency lab (experimental)

Based on the exact 0.3.2 Final tag. Stable release remains unchanged. No bitrate, resolution, compressed queue capacity/order, decoder implementation, audio policy or RAW controls changes. The VPK uses the same title ID, so installing replaces the app; preserve the stable VPK and settings for rollback.

## Test modes
- Classic: preserves 0.3.2 presentation scheduling and output wait policy.
- Adaptive (default): decoder signals completed frame via Notify; main loop can wake early after a cadence-dependent minimum gap, and can wait at most 2ms (requested timeout) for an in-flight frame near a presentation opportunity. Avoid redundant SDL swaps if no new frame and unchanged cached overlay. At 50+ estimated fps, shorten the pending output wait to 4ms when AU age >=18ms with at least one more AU queued. Normal 30fps policy retained.
- Extreme: earlier wake opportunity (12ms for fast stream), requested late wait up to 3ms, aggressive 2ms output wait for an already-late AU, including no later queued AU for fast streams. May trade pacing for freshness. Optional HIGH decoder thread priority on existing USER_2 core, set at worker creation; reconnect between tests. RTC already TIME_CRITICAL on USER_1; no further elevation, audio and input priorities unchanged. No clock changes, no extra textures, no new GPU synchronization assumptions. The requested timers are not guaranteed scheduling precision.

All modes retain normal maintenance deadline and input/overlay handling. A ready signal is revalidated against pending state; no decoder blocking on async render. No change to physical screen refresh or SDL/GXM scanout. CPU-side presentation interval is not display vblank.

## Compare
Same title, region, network, quality profile and scene. Restart stream after each mode change. Warm up 60s and play 5–10 minutes per mode. Compare pipeline average/p95, frame interval p95, actual FPS, output replacements, errors/resync, audio and subjective smoothness. HUD technical view shows mode, wake count, swaps saved and p95. p95 is nearest rank of up to 256 successful telemetry samples per reporting window, not a full-session percentile. Counters are session-local. Keep classic mode or reinstall 0.3.2 if artifacts, frame drops, audio glitches or controls regress.

## Real button-to-photon test
Use an external camera at 240fps or highest available, framing both the physical button and Vita display (not screen capture only). Same game, server region and network; choose an immediate visible, repeatable response such as opening a game menu. Record at least 20 presses per version/mode, spaced apart. Count frames from first visible button actuation to first visible screen response. At 240fps each frame is 4.167ms; physical button actuation is approximated by visible motion, with camera exposure/rolling shutter uncertainty. Report median and p95, not only best result. Repeat 0.3.2 and 0.3.3 classic/adaptive/extreme. Do not add RTT to local pipeline and claim total input latency. No claim of 25–35ms until actual measurements. No hardware test has been performed for 0.3.3 yet.
