# GreenVita 0.3.2 candidate validation

Base: v0.3.1 Final. Independent Rust implementations inspired by documented VitaPlus behavior; no AGPL code incorporated.

- Verify login migration from v1 and legacy JSON to AES-256-GCM (domain-separated key in Safe Memory), restart and logout. Test interrupted/failed writes; never upload vault files. A downgrade to 0.3.1 cannot read v2 and may require a fresh login.
- Verify 720p xCloud and xHome, 6/10/15 Mbps profiles, sound and controls against 0.3.1 under the same network. Do not assert physical latency gains from local timings.
- Test 4 ms native input option on handheld, touch quadrants, View hold/tap, guide, pause, controller remap, stale input and neutral release. Native option off by default; external controllers use SDL. Test PS TV separately.
- Test Wi-Fi interruption, suspend/resume, cancel allocation, restart, session cleanup and absence of old audio. Recovery requires explicit fresh Play after lifecycle interruption.
- Check adaptive RTP wait and short presentation wait under backlog; H.264 compressed order is preserved by the new presentation policy. Verify first frame, decoder resync, and no texture corruption.
- Review ux0:data/xcloud-rust/connection-status.txt (fixed events, numeric aggregates, bounded queue); never attach tokens or account files.
- Verify catalogue scrolling and cover loading, memory and remapping persistence.
- Compilation alone is not device validation. Do not publish as stable until physical acceptance.

## Same-version stability pass

Quality/Balanced retain conservative presentation waits; jitter headroom remains bounded. Audio sessions are isolated by output identity and decoder retirement, with paced retries and profile reset. Test repeated start/stop and audio failures. Transport pump retries are bounded with backoff and pending HTTP tasks cancelled. Diagnostic records append with five-second metrics and two bounded segments (connection-status.txt and .previous). Artwork uses bounded downloads and decode limits with failure cooldown. Settings saves use staged verification and backup recovery; auth errors omit remote response bodies. Validate memory use, smoothness and battery on device, not inferred from compilation.

## Image integrity pass (same 0.3.2)

A missing/invalid access unit or decoder queue overflow now invalidates compressed references and waits for an accepted IDR instead of continuing with damaged references. The last good displayed image is retained; the trade-off is possible short freezes until recovery. Failed decode output is not published and the failed generation is blocked. PLI retries stay rate limited. Quality uses 48–96 ms reordering and at least four compressed queue slots (maximum six), with bounded future packet lookahead. Actual received bitrate, requested bitrate, dependent drops and waiting state are recorded separately. Compression artifacts from the remote encoder may remain. Test identical titles/network and compare visible corruption, freezes, rx_kbps/requested_kbps, drops/dependent/errors/waiting, using the original 0.3.2 artifact for comparison. No new release or version bump.

## Video regression rollback (supersedes prior video experiments)

User reported worse visual corruption. Restored v0.3.1 Final's RTP assembly, reorder policy, decoder queue and reference recovery, session keyframe scheduling, direct texture synchronization, presentation and video metrics. The hardware decoder and bitrate controller were already unchanged. Only rate-limited aggregate logging remains added to the original media receiver. Previous experimental video policy claims above are historical, not active. AES-GCM vault, audio, controls, catalog, and lifecycle changes remain. This does not prove the cause of the device regression; compare the same game, network and settings on real hardware. No new version or release.
