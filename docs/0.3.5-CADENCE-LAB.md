# 0.3.5 beta.1 — cadence experiment
Based on 0.3.4 Final (7394fe4). No release/tag publication. Keep Public single-output, triple BGR565, 720p input and 960x544 output, 64-byte padding, audio and input unchanged. Require self-contained compatible SPS/PPS/IDR before first submit and after genuine decoder errors/queue saturation. No arbitrary compressed-frame skipping during healthy playback; no preventive restart. Use monotonic 90 kHz decoder timestamps following actual RTP deltas (bounded discontinuity fallback), with independent submission ordinal for true measured frame lag. Eight consecutive RTP intervals switch 30/60 cadence classification. Compressed queue capacity targets 80 ms of frame time, bounded 2–6 entries; on existing overflow invalidate queued generation and request clean IDR rather than continue a broken reference chain. This is not a hard bound on hardware DPB residence. Log rate transitions, startup skips, no-output NAL masks/timestamps/intervals and samples exceeding 100 ms. HUD reports cadence and budget violations. The change tests whether PTS cadence influences hardware retention; no guarantee, no fabricated PTS matches. Compare actual 30/60 benchmarks separately. Test log b351.txt (and .previous when rotated).

## Beta 2
Restore 0.3.4 normal compressed queue sizing (2–6, six at 60 fps), reserve all six slots for initial/recreated decoder and self-contained IDR. Queue saturation no longer increments generation or requests hardware recreation. Preserve already accepted AUs; reject subsequent dependent pictures until an IDR can actually be enqueued. Genuine decoder errors and existing damaged-stream recovery remain. Rate-limit overflow logging to once per second, report recovery and raise common PLI cooldown from 300 to 500 ms. Keep Beta 1 RTP-based PTS and cadence instrumentation, strict clean initial IDR, image/audio and log cleanup. No change to public decoder API or SPS. This corrects a known feedback loop, not proof of lower hardware latency. Test build 352 at both rates, then rate transitions. Log connection-status-b352.txt and .previous. No stable release publication.

## Beta 3
Combined experiment: request 960x544 via Xbox client device metadata and control messages, leave SDP and maximum 720p acceptance unchanged for host compatibility. At a complete compatible SPS/PPS/IDR select exact 960x544 decoder dimensions or 720p fallback. Allocate 4 reference slots without changing received SPS; prefer USER_MAIN_PHYCONT_NC_RW rounded to 1 MiB, fall back across CDRAM/1-ref configurations if initialization fails. Record actual allocation, effective clocks, per-window separate successful picture/empty call counts, average, maximum and >16ms count. Keep Public, one output slot, triple BGR565, Beta 2 queue recovery and original audio. Count pre-IDR skipped AUs in video drops. No arbitrary P-frame drops, no speculative flush, no new API. Actual encoded resolution must be verified by SPS. Log b353. Experimental only; no release.
