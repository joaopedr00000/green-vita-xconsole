# 0.3.5 beta.1 — cadence experiment
Based on 0.3.4 Final (7394fe4). No release/tag publication. Keep Public single-output, triple BGR565, 720p input and 960x544 output, 64-byte padding, audio and input unchanged. Require self-contained compatible SPS/PPS/IDR before first submit and after genuine decoder errors/queue saturation. No arbitrary compressed-frame skipping during healthy playback; no preventive restart. Use monotonic 90 kHz decoder timestamps following actual RTP deltas (bounded discontinuity fallback), with independent submission ordinal for true measured frame lag. Eight consecutive RTP intervals switch 30/60 cadence classification. Compressed queue capacity targets 80 ms of frame time, bounded 2–6 entries; on existing overflow invalidate queued generation and request clean IDR rather than continue a broken reference chain. This is not a hard bound on hardware DPB residence. Log rate transitions, startup skips, no-output NAL masks/timestamps/intervals and samples exceeding 100 ms. HUD reports cadence and budget violations. The change tests whether PTS cadence influences hardware retention; no guarantee, no fabricated PTS matches. Compare actual 30/60 benchmarks separately.
